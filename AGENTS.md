# AGENTS.md

Sheafly is a self-hosted, Notion-style notes app: a React PWA plus a small Node server, in an npm workspaces monorepo. See [README.md](README.md) for features, configuration, the sync design and the project layout.

## Build and test

Requires Node 24+. Run everything from the repo root (there is one `package-lock.json`):

```bash
npm install
npm run lint          # oxlint, every workspace
npm run typecheck     # tsc, every workspace
npm test              # client (Vitest) + server (node:test)
npm run test:coverage # same, with coverage thresholds that fail the run
npm run build         # client production build
```

Target one workspace with `-w @sheafly/client`, `-w @sheafly/server` or `-w @sheafly/shared`. CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs lint, typecheck, both test suites, the build and a Docker build, so run the same commands before finishing.

## Architecture

- `apps/server`: Fastify + Drizzle on the built-in `node:sqlite`. **No build step**: Node runs the `.ts` files directly (type stripping), so:
  - relative imports must end in `.ts` (`import { openDb } from './db/index.ts'`)
  - only erasable TypeScript is allowed (no `enum`, `namespace`, or constructor parameter properties)
- `apps/client`: React 19 + Vite PWA, TipTap editor, Dexie (IndexedDB), Tailwind CSS v4.
- `packages/shared`: types only, imported by both apps as `@sheafly/shared`. Change API and note shapes here first.
- The client is offline-first: it writes to IndexedDB, then the sync engine pushes dirty notes to `POST /api/sync` (last-writer-wins per note on `updatedAt`).

## Conventions

- **Commits must follow [Conventional Commits](https://www.conventionalcommits.org)** (`feat:`, `fix:`, `chore:`, `ci:`, `docs:` …). A commitlint hook rejects anything else, including body lines over 100 characters. `feat`/`fix`/`perf` and breaking changes create releases, so pick the type deliberately.
- **Never edit `CHANGELOG.md` or `version` fields by hand.** semantic-release owns them ([.releaserc.json](.releaserc.json)).
- **Database schema**: one file per table in `apps/server/src/db/schema/`, with relations in `relations.ts` there. After changing the schema, run `npm run db:generate -w @sheafly/server` and commit the new folder in `apps/server/drizzle/`. Never edit an already-committed migration. Migrations run automatically on startup.
- **Don't rename persisted identifiers**: the IndexedDB name `notes-app`, the `notes.*` localStorage/sessionStorage keys, the `notes.db` file, and the `notes-app_notes-data` Docker volume. Renaming them logs users out or orphans their data.
- **Styling**: Tailwind utilities in JSX, using the theme colors from [apps/client/src/index.css](apps/client/src/index.css) (`bg-bg`, `text-fg`, `text-muted`, `text-faint`, `border-line`, `bg-accent` …). Dark mode works by swapping those variables, so don't add `dark:` variants. Editor content (HTML generated by TipTap) is styled under `.prose` in the same file.
- **Tests sit next to the code** (`*.test.ts(x)` in the client, `apps/server/test/` for the server). Client tests use a fake IndexedDB and jsdom stubs from [apps/client/src/test/setup.ts](apps/client/src/test/setup.ts). Server tests build the app with `makeApp()` from [apps/server/test/helpers.ts](apps/server/test/helpers.ts) and an in-memory database.
- **Design decisions live in [`docs/agent/`](docs/agent/)** (one file per topic, e.g. [`better-auth-migration.md`](docs/agent/better-auth-migration.md)). Read the relevant design doc before changing the area it covers, and update it as decisions are made.
